## 二、WSL（Windows Subsystem for Linux）使用

### 背景

换新公司了,电脑os也从linux变成了windows。日常开发的时候在终端使用的时候总觉得不是很方便，所以尝试使用wsl。

### 什么是 wsl

WSL全称Windows Subsystem for Linux（Windows上的Linux子系统）。这套设施是微软推出的，为开发者们提供了很大的便利。

想要在一台机器上同时拥有Windows和Linux，传统的做法有两种。一是设置双引导，即安装双系统。二是先安装Windows，再安装个虚拟机软件（例如VMware），最后在虚拟机上安装Linux。但这两种方式的弊端都很明显，除了安装流程麻烦之外，前者切换系统必须重启计算机，后者则因虚拟机这一层导致系统性能比较差。

WSL通过Windows NT内核层面支持了Linux的内核接口，使得Linux环境能直接安装在Windows上。

**注：WSL只在win10的较新版本之后才支持。**

### 安装 wsl

1、以管理员身份打开 PowerShell

```bash
wsl --install
```

这个方式会默认使用wsl 2以及ubuntu

2、重启电脑

3、验证是否成功

```bash
wsl -l v
```

预期成功结果：

```
  NAME      STATE           VERSION
* Ubuntu    Running         2
```

### 在 vscode 中使用 wsl

1、安装wsl插件，名称就叫做WSL

2、在连接远程的地方就会出现WSL目标，直接连接就可以了

![wsl](/pict/wsl.png)

### 常见问题

**0、wsl和windows是两套，安装依赖也需要两套。** 比如 npm，python 等依赖。

**1、wsl install 安装不了**，可以通过代理服务器的方式实现，确保代理服务器可以与外部网络通信（代理原理参见 [三、代理 Clash 工具](#代理-clash-工具)）：

```
$env:HTTP_PROXY="http://127.0.0.1:10809"; $env:HTTPS_PROXY="http://127.0.0.1:10809"; wsl --install
```

**2、wsl 中使用 git 的时候出现中文乱码的问题：**

先检查系统支持哪些 locale，如果没有执行安装中文 locale：

```bash
sudo apt update && sudo apt install -y locales
```

设置默认的 locale：

```
vi ~/.bashrc

# 文件末尾添加
export LANG=zh_CN.UTF-8
export LC_ALL=zh_CN.UTF-8
export LC_CTYPE=zh_CN.UTF-8

# 执行生效
source ~/.bashrc
```

**3、如果 `sudo apt update && sudo apt install -y locales` 运行太慢了**，可更换为阿里源：

1、备份源文件

```bash
sudo cp /etc/apt/sources.list /etc/apt/sources.list.bak
```

2、编辑源文件

```bash
sudo vi /etc/apt/sources.list
```

3、添加阿里源

```
deb http://mirrors.aliyun.com/ubuntu/ focal main restricted universe multiverse
deb-src http://mirrors.aliyun.com/ubuntu/ focal main restricted universe multiverse
deb http://mirrors.aliyun.com/ubuntu/ focal-security main restricted universe multiverse
deb-src http://mirrors.aliyun.com/ubuntu/ focal-security main restricted universe multiverse
deb http://mirrors.aliyun.com/ubuntu/ focal-updates main restricted universe multiverse
deb-src http://mirrors.aliyun.com/ubuntu/ focal-updates main restricted universe multiverse
deb http://mirrors.aliyun.com/ubuntu/ focal-backports main restricted universe multiverse
deb-src http://mirrors.aliyun.com/ubuntu/ focal-backports main restricted universe multiverse
deb http://mirrors.aliyun.com/ubuntu/ focal-proposed main restricted universe multiverse
deb-src http://mirrors.aliyun.com/ubuntu/ focal-proposed main restricted universe multiverse
```

4、保存退出即可。

**4、如果 `npm install` 时候太慢了，wsl 如何解决：**

1. 切换 npm 镜像源。最直接的方式，将 npm 源换为国内镜像：

   ```bash
   # 切换为淘宝镜像
   npm config set registry https://registry.npmmirror.com

   # 验证是否生效
   npm config get registry
   ```

   或者使用 nrm 快速切换：

   ```bash
   npm install -g nrm
   nrm ls          # 查看可用源
   nrm use taobao  # 切换到淘宝源
   ```

2. 项目放在 Linux 文件系统中（关键）。这是 WSL 特有的问题。如果项目放在 `/mnt/c/` 或 `/mnt/d/`（Windows 文件系统），WSL 需要通过 9P 协议跨系统访问，I/O 性能会大幅下降。把项目移到 Linux 原生文件系统下：

   ```bash
   # 推荐：放在 home 目录下
   cp -r /mnt/d/code/your-project ~/projects/your-project
   cd ~/projects/your-project
   npm install
   ```

   速度差异可以达到 5-10 倍。

## 三、开发工具使用

### 代理 Clash 工具

- **https_proxy**: HTTPS 下需要走代理
- **http_proxy**: HTTP 下需要走代理

上述配置通常配置在 `~/.bashrc` 中作为环境变量设置。WSL 安装时的代理用法见 [二、WSL 常见问题](#常见问题)。

### Python 包管理工具

#### Poetry vs 传统方式

Poetry = pip + venv + requirements.txt + setup.py + twine 的终极升级版

Poetry 是一个现代化的 Python 项目依赖管理和打包工具 -- 它帮你一键搞定项目初始化、依赖安装、虚拟环境管理、打包发布等所有 "Python 开发中的脏活累活"。

#### uv 工具介绍

uv 是一个用 Rust 编写的、超快的 Python 包管理器和环境工具，由 Astral 团队开发（也是 ruff -- 最快的 Python linter 的作者团队）。它被设计为 pip + venv + poetry + pip-tools 的现代替代品，目标是：比现有工具快 10–100 倍。

#### 包管理工具对比

| 功能 | `pip` | `poetry` | `uv` |
| :--- | :--- | :--- | :--- |
| **速度** | ⚠️ 慢（Python 实现） | ✅ 中等 | ✅✅✅ **极快**（Rust 实现） |
| **虚拟环境** | 手动创建 | 自动创建 | 自动创建（更快） |
| **依赖声明** | `requirements.txt` | `pyproject.toml` | ✅ 支持两者 |
| **锁定文件** | ❌ 无标准 | `poetry.lock` | `uv.lock`（兼容性好） |
| **开发依赖分组** | ❌ 不支持 | ✅ 支持 | ✅ 支持 |
| **打包发布** | 需 `setuptools` + `twine` | 内置 `poetry build` | 内置 `uv build` |
| **多版本 Python 支持** | 需 `pyenv` | 需 `pyenv` | 内置支持（自动下载） |
| **社区生态** | 老牌标准 | 成熟流行 | 新兴，增长极快（2024 年爆火） |
| **是否推荐新项目使用** | ❌ 已过时 | ✅ 推荐 | ✅✅ **强烈推荐（未来趋势）** |

#### uv 常见命令

| 命令 | 功能 |
| :--- | :--- |
| `uv python list` | 查看本机有哪些 Python 版本 |
| `uv venv --python 3.12` | 虚拟环境中指定版本 |

#### uv 创建一个项目的流程

```bash
# wsl 中安装 uv
pip install uv -i https://pypi.tuna.tsinghua.edu.cn/simple
uv --version

# 构建一个 uv 项目的流程
uv init
uv venv
source .venv/bin/activate
uv add requests
```

### vscode 中常见的操作

#### 设置常用的项目根目录路径

设置类似 pycharm 中的环境变量，在项目的根目录下建立 `./env` 文件。

**方式 1：** 假设你的根目录是 **src** 文件，那么你在 `.env` 中可以这样设置

```
PYTHONPATH=./src
```

配置完之后，执行以下 python 代码进行测试：

```python
import os
from dotenv import load_dotenv
import sys

# 显式加载.env文件
print("当前工作目录:", os.getcwd())
load_dotenv(verbose=True)  # verbose=True 会打印加载信息
# 打印环境变量
print("\n测试变量:", os.environ.get("TEST_VAR"))
print("\nPYTHONPATH:", os.environ.get("PYTHONPATH"))
# 打印所有Python路径
print("\n所有Python搜索路径:")
for path in sys.path:
    print(path)
```

**方式 2：** 直接设置 settings.json（**推荐使用这种方式**，设置之后一定要重启 vscode）

```json
{
  "python.analysis.extraPaths": [
    "${workspaceFolder}/openans-analyser-aichatops/src"
  ]
}
```

### Python 镜像源与虚拟环境配置

1. 安装指定源之下的包
   - `pip3 install pytest -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com`
   - `pip3 install pytest -i https://pypi.mirrors.ustc.edu.cn/simple/ --trusted-host pypi.mirrors.ustc.edu.cn`
   - `pip3 install pytest -i http://pypi.douban.com/simple/ --trusted-host pypi.douban.com`
   - `pip3 install joblib -i https://pypi.tuna.tsinghua.edu.cn/simple/ --trusted-host pypi.tuna.tsinghua.edu.cn`
2. 配置全局源
   - 查看当前镜像：`pip config list`
   - `pip config set global.index-url https://artsz.zte.com.cn/artifactory/api/pypi/public-pypi-virtual/simple`
   - `pip config set install.trusted-host artsz.zte.com.cn`
3. python 中创建虚拟环境
   - 安装 virtualenv：`pip install virtualenv`
   - 创建一个名为 myenv 的虚拟环境：`virtualenv myenv`
   - 激活虚拟环境：`source myenv/bin/activate`
   - 退出虚拟环境：`deactivate`
   - 删除虚拟环境：`rm -rf myenv`

## 四、总结与建议

### 安装注意事项

1. **备份重要数据**：在进行系统安装或重装前，务必备份个人文件
2. **检查系统要求**：确保硬件满足软件的最低要求
3. **使用官方或可信源**：避免使用来路不明的安装包

### 学习资源推荐

1. **官方文档**：始终优先查阅官方安装指南
2. **技术社区**：如 CSDN、博客园等平台有丰富的实践经验分享
3. **视频教程**：B站等平台的视频教程更直观易懂

### 故障排除思路

1. **错误信息分析**：仔细阅读错误提示，理解问题根源
2. **日志检查**：查看系统日志获取更多调试信息
3. **社区求助**：在技术论坛或社区提问时，提供详细的错误信息和操作步骤
